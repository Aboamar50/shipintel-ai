# ShipIntel AI

واجهة عربية وإنجليزية لإدارة الشحنات. يمكن تشغيلها كتجربة محلية، أو نشرها كموقع ثابت وربطها بمشروع Supabase لحفظ الحسابات والشحنات في السحابة.

## ما الذي يعمل الآن؟

- صفحة تعريفية في `index.html` ولوحة تشغيل في `dashboard.html`.
- بحث وتصفية وإضافة وتعديل وحذف الشحنات وتصدير CSV.
- إعداد Vercel لموقع ثابت مع ترويسات أمان أساسية (`vercel.json`).
- تكامل اختياري مع Supabase: تسجيل حساب وبريد إلكتروني، تسجيل دخول وخروج، إعادة تعيين كلمة المرور، وحفظ الشحنات في قاعدة بيانات.
- سياسات Row Level Security تعزل شحنات كل مستخدم، وتتيح للمدير المعتمد إدارتها جميعًا.
- يبقى وضع العرض المحلي متاحًا إذا لم تُضف إعدادات Supabase؛ بياناته التجريبية لا تُرفع أو تُدمج تلقائيًا إلى قاعدة البيانات.

## 1. نشر الموقع مجانًا على Vercel

1. أنشئ حسابًا مجانيًا على [vercel.com](https://vercel.com) وسجّل الدخول باستخدام حساب GitHub الذي يملك المستودع.
2. اختر **Add New → Project**، ثم استورد المستودع `Aboamar50/shipintel-ai` واسمح لـ Vercel بالوصول إليه.
3. استخدم الإعدادات الافتراضية لموقع ثابت: لا تختَر إطار عمل، ولا تضف أمر بناء أو تثبيت حزم، واترك مجلد الإخراج الافتراضي دون تغيير.
4. اختر **Deploy**. بعد نجاح النشر سيعطيك Vercel رابطًا ينتهي عادةً بـ `vercel.app`. اختبر الصفحة الرئيسية ثم زر «ابدأ الآن».
5. بعد ربط المستودع، كل `git push` إلى `main` ينشئ نشرًا جديدًا تلقائيًا. يمكن إضافة نطاق خاص لاحقًا من إعدادات المشروع.

الموقع الحالي صفحات HTML ثابتة؛ لا يحتاج إلى خادم أو متغيرات بيئة في Vercel. ملف `vercel.json` يضيف ترويسات أمان فقط.

## 2. إنشاء قاعدة بيانات Supabase وربطها

1. أنشئ مشروعًا مجانيًا على [supabase.com](https://supabase.com). احتفظ بكلمة مرور قاعدة البيانات في مدير كلمات مرور، ولا تضعها في هذا المستودع.
2. في لوحة المشروع افتح **SQL Editor → New query**. الصق محتوى [`database/setup.sql`](./database/setup.sql) كاملًا ثم اختر **Run**. ينشئ هذا الملف الجداول، وملف المستخدم، ومشغّل إنشاء الملف الشخصي، وسياسات العزل والصلاحيات.
3. من **Project Settings → API** انسخ **Project URL** ومفتاح **Publishable key** (أو مفتاح `anon` القديم). لا تستخدم مفتاح `service_role` أو أي مفتاح سري في موقع المتصفح.
4. افتح [`assets/supabase-config.js`](./assets/supabase-config.js) واستبدل القيمتين التجريبيتين فقط:

   ```js
   window.SHIPINTEL_SUPABASE_CONFIG = Object.freeze({
       url: 'https://YOUR_PROJECT_REF.supabase.co',
       anonKey: 'YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY'
   });
   ```

   مفتاح `publishable`/`anon` مخصص للعميل ويمكن أن يظهر في الموقع؛ أمان البيانات يعتمد على سياسات RLS التي ينشئها ملف SQL، وليس على إخفاء هذا المفتاح.
5. في Supabase افتح **Authentication → URL Configuration**. اجعل **Site URL** رابط Vercel المنشور، وأضف إلى **Redirect URLs** رابط الموقع وروابط التطوير المحلية، مثل:

   ```text
   https://YOUR-PROJECT.vercel.app/**
   http://localhost:5500/**
   ```

   استبدل `YOUR-PROJECT` برابطك الحقيقي. إذا استخدمت منفذًا محليًا آخر، أضف ذلك الرابط والمنفذ بدلًا من `5500`.
6. افتح **Authentication → Providers → Email** واختر سياسة تأكيد البريد التي تريدها، واضبط الحد الأدنى لكلمة المرور على 8 أحرف على الأقل. الحسابات التي تتطلب تأكيد البريد لن تتمكن من الدخول قبل الضغط على رابط التأكيد.
7. احفظ ملف الإعداد ثم نفّذ `git add assets/supabase-config.js`, و`git commit -m "Configure Supabase client"`, و`git push`. سيعيد Vercel النشر تلقائيًا. لا تُضف كلمات مرور قاعدة البيانات أو مفاتيح `service_role` إلى أي ملف أو commit.
8. افتح رابط الموقع، وأنشئ حسابًا من صفحة لوحة التحكم. أضف الشحنات من داخل الحساب؛ لا تُنقل بيانات العرض التجريبية تلقائيًا إلى السحابة.

للاختبار المحلي، شغّل الموقع عبر إضافة VS Code مثل **Live Server** وافتح العنوان `http://localhost:5500`؛ لا تستخدم `file://` مع تسجيل الدخول، لأن مزود الهوية يحتاج عنوان HTTP مسموحًا به.

## 3. حساب المدير والصلاحيات

- التسجيل الذاتي ينشئ مستخدمًا بدور `user`. لا يستطيع المستخدم تغيير دوره من الواجهة أو تعديل شحنات مستخدم آخر.
- بعد إنشاء حسابك وتأكيد البريد، افتح **SQL Editor** في Supabase وشغّل الاستعلام التالي بعد استبدال البريد ببريدك (إذا احتوى البريد على علامة اقتباس مفردة، كررها في SQL):

  ```sql
  update public.profiles
  set role = 'admin'
  where id = (
      select id from auth.users
      where email = lower('you@example.com')
  );
  ```

- يمنح دور `admin` صلاحية قراءة الشحنات وتعديلها وحذفها عبر سياسات RLS. منح هذا الدور يتم من لوحة Supabase الموثوقة فقط، وليس من المتصفح.
- لا تمنح دور المدير إلا لحساب تملكه وتتحكم ببريده الإلكتروني. تطبيق سياسات إضافية لإدارة المستخدمين أو الدعوات يتطلب واجهة/خدمة إدارية موثوقة، ولا تستخدم مفتاح `service_role` في الواجهة.

## تشغيل محلي دون إعداد سحابي

افتح `index.html` أو استخدم إضافة Live Server. عند بقاء القيم التجريبية في ملف إعداد Supabase، تعمل لوحة التحكم بوضع محلي ببيانات العرض؛ وهي محفوظة في متصفحك فقط. لا تعمل المصادقة أو المزامنة السحابية قبل إنشاء المشروع وتعبئة إعداداته وتشغيل SQL.

## حدود النسخة الحالية

تخزين الحسابات والشحنات السحابي يصبح فعّالًا بعد إكمال إعداد Supabase. بيانات البداية المحلية تجريبية وليست مستوردة إلى قاعدة البيانات. التتبع يعرض المعلومات التي يدخلها المستخدم فقط؛ لا يوجد تكامل حالي مع واجهات شركات الشحن أو بيانات سفن حية. روابط النشر وقواعد البيانات تظل غير فعالة إلى أن تنشئ الحسابات وتربط المستودع بنفسك.
