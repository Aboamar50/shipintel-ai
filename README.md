# ShipIntel AI

منصة عربية وإنجليزية لإدارة الشحنات، مع العربية كلغة افتراضية. يمكن تشغيلها كتجربة محلية، أو نشرها كموقع ثابت وربطها بمشروع Supabase لحفظ الحسابات والشحنات في السحابة.

## ما الذي يعمل الآن؟

- صفحة دخول عامة في `index.html` تعرض هوية ShipIntel AI، تسجيل الدخول، ووسائل التواصل فقط.
- لوحة داخلية في `dashboard.html` لا تُظهر أقسام التشغيل إلا بعد مصادقة حساب مخوّل؛ أقسام الرئيسية وتتبع الشحنات والمسارات والباقات مستقلة.
- بحث وتصفية وإضافة وتعديل وحذف الشحنات وتصدير CSV.
- لوحة مسارات تشغيلية ببحث وتصفية حسب الحالة، مرتبطة بسجلات الشحنات المحفوظة؛ الخريطة التوضيحية لا تعرض مواقع سفن آنية، وأسماء السفن ومعرّفات الرحلات غير متاحة ما لم تُسجّل.
- واجهة ثنائية اللغة (العربية والإنجليزية) مع تبديل فوري واتجاه RTL/LTR، وتسجيل دخول مغلق للمستخدمين المدعوين فقط.
- رابط واتساب مباشر لطلب عرض سعر أو نسخة تجريبية، برسالة تتبع اللغة المختارة.
- إعداد Vercel لموقع ثابت مع ترويسات أمان أساسية (`vercel.json`).
- تكامل اختياري مع Supabase: دعوات حسابات الموظفين، تسجيل الدخول والخروج، إعادة تعيين كلمة المرور، وحفظ الشحنات في قاعدة بيانات.
- سياسات Row Level Security تقصر بيانات وعمليات الشحنات على موظفي التخليص والمدير، وتتيح للمدير المعتمد إدارتها جميعًا.
- يتوفر وضع تجريبي محلي فقط عند التشغيل من `file://` أو `localhost` ببيانات `admin` / `12345678`؛ لا تستخدمه لحماية بيانات حقيقية أو على موقع منشور.

## 1. نشر الموقع مجانًا على Vercel

1. أنشئ حسابًا مجانيًا على [vercel.com](https://vercel.com) وسجّل الدخول باستخدام حساب GitHub الذي يملك المستودع.
2. اختر **Add New → Project**، ثم استورد المستودع `Aboamar50/shipintel-ai` واسمح لـ Vercel بالوصول إليه.
3. استخدم الإعدادات الافتراضية لموقع ثابت: لا تختَر إطار عمل، ولا تضف أمر بناء أو تثبيت حزم، واترك مجلد الإخراج الافتراضي دون تغيير.
4. اختر **Deploy**. بعد نجاح النشر سيعطيك Vercel رابطًا ينتهي عادةً بـ `vercel.app`. اختبر الصفحة الرئيسية ثم زر «ابدأ الآن».
5. بعد ربط المستودع، كل `git push` إلى `main` ينشئ نشرًا جديدًا تلقائيًا. يمكن إضافة نطاق خاص لاحقًا من إعدادات المشروع.

الموقع الحالي صفحات HTML ثابتة؛ لا يحتاج إلى خادم أو متغيرات بيئة في Vercel. ملف `vercel.json` يضيف ترويسات أمان فقط.

## 2. إنشاء قاعدة بيانات Supabase وربطها

1. أنشئ مشروعًا مجانيًا على [supabase.com](https://supabase.com). احتفظ بكلمة مرور قاعدة البيانات في مدير كلمات مرور، ولا تضعها في هذا المستودع.
2. في لوحة المشروع افتح **SQL Editor → New query**. الصق محتوى [`database/setup.sql`](./database/setup.sql) كاملًا ثم اختر **Run**. ينشئ هذا الملف الجداول، وملف المستخدم، ومشغّل إنشاء الملف الشخصي، وسياسات العزل والصلاحيات.
3. من **Project Settings → API** انسخ **Project URL** ومفتاح **Publishable key** (أو مفتاح `anon` القديم). لا تستخدم مفتاح `service_role` أو أي مفتاح سري في موقع المتصفح.
4. افتح [`assets/supabase-config.js`](./assets/supabase-config.js) واستبدل القيمتين التجريبيتين فقط:

   ```js
   window.SHIPINTEL_SUPABASE_CONFIG = Object.freeze({
       url: 'https://YOUR_PROJECT_REF.supabase.co',
       anonKey: 'YOUR_PUBLIC_PUBLISHABLE_OR_ANON_KEY'
   });
   ```

   مفتاح `publishable`/`anon` مخصص للعميل ويمكن أن يظهر في الموقع؛ أمان البيانات يعتمد على سياسات RLS التي ينشئها ملف SQL، وليس على إخفاء هذا المفتاح.
5. في Supabase افتح **Authentication → URL Configuration**. اجعل **Site URL** رابط Vercel المنشور، وأضف إلى **Redirect URLs** رابط الموقع وروابط التطوير المحلية، مثل:

   ```text
   https://YOUR-PROJECT.vercel.app/**
   http://localhost:5500/**
   ```

   استبدل `YOUR-PROJECT` برابطك الحقيقي. إذا استخدمت منفذًا محليًا آخر، أضف ذلك الرابط والمنفذ بدلًا من `5500`.
6. افتح **Authentication → Providers → Email** واضبط الحد الأدنى لكلمة المرور على 8 أحرف على الأقل. عطّل **Allow new users to sign up** (التسجيل العام) قبل النشر؛ يجب أن ينشئ المدير حسابات موظفي التخليص عبر **Authentication → Users → Invite user**. الحسابات التي تتطلب تأكيد البريد لن تتمكن من الدخول قبل الضغط على رابط التأكيد.
7. احفظ ملف الإعداد ثم نفّذ `git add assets/supabase-config.js`, و`git commit -m "Configure Supabase client"`, و`git push`. سيعيد Vercel النشر تلقائيًا. لا تُضف كلمات مرور قاعدة البيانات أو مفاتيح `service_role` إلى أي ملف أو commit.
8. من **Authentication → Users** أرسل دعوة إلى بريد كل موظف، ثم يفتح الموظف رابط الدعوة ويُكمل إنشاء كلمة المرور. لا يوجد تسجيل ذاتي في واجهة الموقع. الحساب الجديد يبدأ بدور `user` ولا يستطيع فتح لوحة التشغيل؛ بعد الدعوة، رقِّه إلى `customs_agent` كما هو موضح أدناه. أضف الشحنات من داخل الحساب؛ لا تُنقل بيانات العرض التجريبية تلقائيًا إلى السحابة.

للتجربة السريعة محليًا، افتح `index.html` أو شغّله عبر إضافة **Live Server** على `localhost`، ثم استخدم اسم المستخدم `admin` وكلمة المرور `12345678`. هذا وضع تجريبي غير آمن، موجود للتجربة المحلية فقط ويستخدم بيانات محفوظة في المتصفح؛ لا تنشره ولا تستخدمه مع بيانات حقيقية. لتجربة Supabase محليًا استخدم حسابًا حقيقيًا وأضف رابط التطوير إلى قائمة Redirect URLs.

## 3. دعوات الموظفين وصلاحيات المدير

- عطّل التسجيل الذاتي من إعدادات Supabase، وأنشئ حسابات موظفي التخليص المصرّح لهم فقط عبر **Authentication → Users → Invite user**. أزل حساب الموظف أو عطّله عند انتهاء صلاحية الوصول.
- الحسابات المدعوة تبدأ بدور `user` ولا تستطيع فتح لوحة التشغيل أو قراءة الشحنات أو تعديلها عبر واجهة Supabase. بعد قبول الدعوة، امنح كل موظف مصرح له دور `customs_agent` من **SQL Editor**، مع استبدال البريد ببريده:

  ```sql
  update public.profiles p
  set role = 'customs_agent'
  from auth.users u
  where p.id = u.id
    and u.email = lower('agent@example.com');
  ```

- يقيّد التطبيق الدخول إلى اللوحة على دوري `customs_agent` و`admin`، وتفرض سياسات RLS هذا القيد أيضًا على طلبات قاعدة البيانات. يستطيع موظف التخليص إدارة شحناته، بينما يستطيع المدير المعتمد الاطلاع على جميع الشحنات وإدارتها.
- بعد دعوة بريدك وإكمال تفعيل حسابك، افتح **SQL Editor** في Supabase وشغّل الاستعلام التالي بعد استبدال البريد ببريدك (إذا احتوى البريد على علامة اقتباس مفردة، كررها في SQL):

  ```sql
  update public.profiles
  set role = 'admin'
  where id = (
      select id from auth.users
      where email = lower('you@example.com')
  );
  ```

- يمنح دور `admin` صلاحية قراءة الشحنات وتعديلها وحذفها عبر سياسات RLS. منح هذا الدور يتم من لوحة Supabase الموثوقة فقط، وليس من المتصفح.
- لا تمنح دور المدير إلا لحساب تملكه وتتحكم ببريده الإلكتروني. بيانات `admin` / `12345678` مخصصة للعرض المحلي فقط، ويمكن رؤيتها في ملفات الواجهة؛ لا تستخدمها على موقع منشور أو مع بيانات حقيقية. يعتمد دخول الموقع المنشور على مصادقة Supabase، وتحمي سياسات RLS بيانات السحابة.

## زر طلب عرض السعر عبر واتساب

رقم التواصل العام مضبوط في `assets/contact-config.js` بصيغة دولية (أرقام فقط). حدّثه إذا تغيّر الرقم. تعرض الصفحة زرين منفصلين: «تواصل عبر واتساب» يفتح محادثة برسالة عربية جاهزة، و«اتصال مباشر / طلب عرض سعر» يفتح اتصالًا هاتفيًا بالرقم نفسه.

## بوابة الدخول واللوحة الداخلية

تعرض `index.html` هوية ShipIntel AI وتسجيل الدخول وروابط التواصل فقط. عند التشغيل المحلي دون إعداد Supabase، تتيح بيانات التجربة `admin` / `12345678` فتح بيانات نموذجية غير آمنة محفوظة محليًا. على المواقع المنشورة، لا يعمل هذا المسار؛ يتطلب الدخول إعداد Supabase والتحقق من دور `customs_agent` أو `admin` قبل عرض بيانات التشغيل.

## حدود النسخة الحالية

تخزين الحسابات والشحنات السحابي يصبح فعّالًا بعد إكمال إعداد Supabase ودعوة الموظفين وتعيين الأدوار. لا يوجد تكامل حالي مع واجهات شركات الشحن أو بيانات سفن حية. رابط واتساب متاح من قائمة لوحة التحكم.
